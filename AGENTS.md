# Перенос глоссария книжных выставок

Источник требований — [план миграции](migration/PLAN_GLOSSARY_MIGRATION.md). Читатель должен найти каждую выставку через указатель и открыть полный оригинальный материал по постоянному адресу. Каталог публикации — `site/`.

## Команда

Профили ролей находятся в [.codex/agents](.codex/agents/). Руководитель переноса назначает сабагентам непересекающиеся пути и передаёт каждому входные данные, ожидаемый результат и способ проверки. Сбор и учёт иллюстраций можно вести параллельно. Писатель начинает выпуск материалов по проверенным записям. Проверяющий независимо сравнивает результат с источником. Роли можно совмещать при ограниченном числе исполнителей, сохраняя независимую приёмку.

| Сабагент | Ответственность | Что передаёт дальше |
| --- | --- | --- |
| Руководитель | Сверяет ветку и план, координирует работы, разбирает расхождения, ведёт итоговый отчёт | Список принятых материалов, открытых вопросов и результаты публикации |
| Архивист | Обходит указатель, вложенные страницы и продолжения, извлекает содержательную разметку | Реестр с адресами, заголовками, порядком текста, ссылок и изображений |
| Хранитель иллюстраций | Проверяет локальные оригиналы, варианты размера, регистр пути и содержимое Git LFS | Соответствия исходным URL, отсутствующие или неоднозначные иллюстрации |
| Писатель-сборщик | Переносит авторские материалы дословно, строит отдельные страницы и алфавитные подборки | Воспроизводимая сборка, карта URL и SEO-файлы |
| Проверяющий | Сверяет с оригиналом текст, структуру, подписи и порядок, тестирует ссылки и ресурсы под префиксом проекта | Воспроизводимые расхождения с конкретными URL и итоги повторной проверки |
| Ответственный за публикацию | Проверяет настройки Pages, выкладывает содержимое site/ и проверяет живые URL | Ссылка на запуск, публичный адрес, HTTP-результаты, включая 404 |

## Работа с материалами

Для сбора источников и иллюстраций используй [glossary-source](.agents/skills/glossary-source/SKILL.md), для сборки, приёмки и релиза — [glossary-publish](.agents/skills/glossary-publish/SKILL.md). Только руководитель интегрирует результаты и отправляет коммиты по поручению пользователя. При передаче задачи указывай изменённые файлы, команду проверки и оставшиеся расхождения.

## Текущее состояние переноса

Материалы собраны, перенесены и опубликованы: **https://r2force.github.io/glossary/**.
Итоговый отчёт — [migration/REPORT_FINAL.md](migration/REPORT_FINAL.md), инвентаризация —
[migration/REPORT_INVENTORY.md](migration/REPORT_INVENTORY.md).

| Шаг | Команда | Результат |
| --- | --- | --- |
| Сбор источника (нужен интернет) | `python migration/tools/harvest.py` | `migration/source/` |
| Разбор в реестр | `python migration/tools/extract.py` | `migration/build/registry.json` |
| Экспорт контента в коллекции Jekyll | `python migration/tools/build_site.py` | `site/_exhibitions/`, `site/_sections/`, `site/index.html`, `site/conclusion/index.html` |
| Сборка статического сайта Jekyll | `BUNDLE_GEMFILE=site/Gemfile bundle exec jekyll build --source site --destination _site --strict_front_matter` | `_site/` |
| Проверка изображений (нужен `git lfs pull`) | `python migration/tools/verify_media.py` | `migration/build/media_report.json` |
| Независимая проверка | `python migration/tools/verify_site.py --site _site --repeat` | `migration/build/verify_report.json` |

Устройство сайта (`site/` — проект **Jekyll**, разделение оформления и содержания, принцип DRY):
- **Шаблоны и оформление** лежат в `site/_layouts/`, `site/_includes/` и `site/assets/site.css`.
- **Верхнее меню и алфавит** вынесены в `site/_data/navigation.yml` (шаблон `site/_includes/nav.html`) и `site/_data/alphabet.yml` (`site/_includes/letter-nav.html`): изменение пункта меню требует правки только одного файла.
- **Содержание** хранится без HTML-каркаса оформления: статьи выставок — в `site/_exhibitions/<slug>.html`, разделы букв — в `site/_sections/<letter>.html`, введение — в `site/index.html`, заключение — в `site/conclusion/index.html`.
- Сборочный каталог `_site/` исключён из Git; публикация идёт из `main` через `.github/workflows/deploy-pages.yml` (задачи `build` → `deploy` → `smoke`).
