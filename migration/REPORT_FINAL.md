каждая выставка дополнительно опубликована отдельной статьёй (`view=article&id=…`) с тем же

не обнаружено.

## 4. Устройство сайта

```text
site/
├── index.html                 главная: указатель А–Я и введение
├── introduction/index.html    введение
├── contents/index.html        алфавитный указатель со всеми 271 ссылками
├── conclusion/index.html      заключение
├── sections/<буква>/          25 страниц разделов (краткие фрагменты и переходы)
├── exhibitions/<slug>/        271 самостоятельная страница выставки
├── images/…                   исходные файлы репозитория
├── assets/site.css            минимальное оформление
├── sitemap.xml, robots.txt, 404.html
```

- Каждая выставка — отдельный HTML-файл и собственный постоянный URL вида
  `https://r2force.github.io/glossary/exhibitions/<slug>/`.
- Страницы разделов содержат названия и краткие фрагменты со ссылками на полные материалы,
  поэтому дублирования полного текста нет.
- Все ссылки на ресурсы относительные; сайт работает и в подпапке `/glossary/`, и локально.
- Генератор: `migration/tools/build_site.py`; повторный запуск даёт те же файлы
  (проверяется `verify_site.py --repeat`).
- Страницы содержат блок «соседние выставки» внутри буквы и хлебные крошки, что связывает
  материалы в сеть внутренних ссылок.

## 5. SEO

- Уникальные `<title>` и `meta description` у каждой страницы (description — первые
  содержательные слова материала, без выдуманных фактов).
- Один `<h1>` на страницу, семантические `<article>`, `<nav>`, `<figure>`, `<ul>`.
- Абсолютный `canonical` у всех страниц, `og:title/description/url`, разметка Schema.org `Article`.
- `sitemap.xml` — 300 адресов, каждый проверен на существование файла.
- `robots.txt` с корректным адресом sitemap.
- `404.html` — своя страница с переходами к указателю.
- Скрытых `noindex` нет, ссылок на старый Joomla-сайт в публикуемом HTML нет.
- `alt` у всех содержательных изображений заполнен осмысленно (заголовок выставки + имя файла
  источника); пустых `alt` нет.

## 6. Публикация

Workflow `.github/workflows/deploy-pages.yml`:

1. Запуск при push в `main` и по `workflow_dispatch`.
2. Checkout с `lfs: true` — получает реальные байты иллюстраций.
3. Пересборка страниц из реестра (`extract.py --from-registry`, `build_site.py`).
4. Проверки: реальность изображений, полнота текста, ссылки, SEO, повторяемость сборки,
   отсутствие LFS-указателей в `site/`.
5. Загрузка в Pages **только** каталога `site/`.
6. Задача `deploy` с `permissions: pages: write, id-token: write`.
7. Задача `smoke`: проверка опубликованного сайта по HTTPS.

Домен `CNAME` в репозитории отсутствует, пользовательский домен не настраивался и не менялся.
Настройка репозитория: `Settings → Pages → Source → GitHub Actions` (уже была активна).

## 8. Известные ограничения и открытые вопросы

1. **Число выставок — 271**, что меньше заявленных во введении «более 270 форм». Это
   соответствует фактическому составу опубликованного сайта: расхождений между карточками
   указателя и отдельными статьями нет. Если существовал более полный печатный вариант,
   на сайте он не опубликован.
2. **Букв Ё, Й, Щ, Ъ, Ы, Ь на источнике нет** — разделы для них не создавались, в указателе
   они показаны как неактивные.
3. **13 файлов изображений не используются** текстами источника (логотип старого шаблона и
   наборы миниатюр `horovod`, `prazdnik`, `test`, `zagadka`). Они сохранены в репозитории,
   но не публикуются как содержимое статей; подстановка «по смыслу» не выполнялась.
4. **Ссылка на локальный файл автора** (`file:///D:/temp/msohtml1/…/clip_image002.gif`)
   в статье «Выставка – акростих» не может быть восстановлена: файла нет ни на сайте, ни в
   репозитории. Ссылка удалена, текст статьи сохранён полностью. Это единственная
   недоступная иллюстрация источника.
5. **Joomla-адреса** внутри текстов заменены простым текстом, чтобы не публиковать ссылки на
   старый сайт; содержательные внешние ссылки сохранены с `rel="nofollow noopener"`.
6. **E-mail в заключении** был скрыт Joomla-скриптом; восстановлен как
   `metodcsdb@gmail.com` по тексту источника — проверьте, если адрес изменился.
7. **Введение на главной** повторяется как раздел «О глоссарии», чтобы главная сразу давала
   содержательный текст; отдельная страница `/introduction/` остаётся канонической.
8. В исходном сборе один адрес (`http://` без TLS) не ответил; содержание получено по HTTPS,
   потерь нет.

## 10. Как воспроизвести

```bash

python migration/tools/build_site.py         # сборка site/
python migration/tools/verify_media.py       # изображения (нужен git lfs pull)
python migration/tools/verify_site.py --repeat
```
